## 0. Two load-bearing facts, two mandatory probes

### 0.1 WAE has no documented subquery / derived-table / window-function support
Every shipped query (`stats.ts`, `pages.ts`, `browsers.ts`, `timeseries.ts`) is a single flat `SELECT ... GROUP BY`. Therefore:

- **Pure dimension breakdowns** (channels, crawlers, active) are trivially feasible — `SELECT blobN, SUM(_sample_interval) ... GROUP BY blobN`, identical in shape to `browsers.ts`.
- **Bounce and duration** are re-architected to run a *flat* `GROUP BY blob12` returning one row per session, then compute the cross-session aggregate **in the TypeScript handler**. No SQL subquery.

**PROBE 1 (do before Phase 4 code):** run `SELECT x FROM (SELECT 1 AS x)` against `/analytics_engine/sql`. Expected 4xx. If so, handler-side aggregation is mandatory; `ROW_NUMBER() OVER (...)` and nested `FROM (SELECT ...)` are off the table.

### 0.2 The empty-string-blob assumption is the single highest-blast-radius bet in this plan
The whole traffic-class design rests on \"WAE returns unset blobs as `''`\". If AE actually returns `NULL`, the moment Phase 0/2 ships, **every** existing endpoint silently returns zero rows for all 90 days of pre-0.2.0 data, because the default human filter `blob10 = ''` matches nothing.

**PROBE 2 (do in Phase 0, before shipping the filter):** on a deployment that holds pre-0.2.0 rows, compare:
```sql
SELECT COUNT() AS c FROM agent_analytics WHERE blob1='<site>' AND blob10 = '';
-- vs the same query with NO blob10 predicate
```
If the counts match, `blob10 = ''` is correct. If unset blobs come back `NULL`, the predicate MUST be `(blob10 = '' OR blob10 IS NULL)`. **Bake the verified predicate into `buildWhereClause` — do not assume.**

> **CRITICAL fix vs the draft (engagement row poisoning):** the draft proposed writing the engagement beacon as a separate AE row with `double1 = 0`, claiming pageview counts would ignore it. **That is false for this codebase — NO shipped query multiplies by `double1`.** `stats.ts:12` is `SUM(_sample_interval) AS pageviews`; `pages.ts:13`, `timeseries.ts:27`, `browsers/referrers/geo` all use bare `SUM(_sample_interval)`. A separate engagement row is a physical AE row that bare `SUM(_sample_interval)` counts as a full pageview, inflating pageviews / views / timeseries / active / channel counts by ~1 per dwell beacon (up to ~2x on engaged single-page visits). **Resolution: introduce `blob16 = event_type` as a row-type discriminator, and make `buildWhereClause` filter `blob16 = 'pv'` by DEFAULT** (the same mechanism as `blob10`). > **Slot-map override vs grounding:** grounding suggested `blob10 = channel`. We override: `blob10` is the *traffic-class* flag because it is filtered on **every** query, so it stays a 2-char value to keep scans cheap. Channel moves to `blob11`. `double3` is intentionally left unused (no `is_entry` needed — bounce is derived from per-session pageview count).

Final usage: 16/20 blobs, 3/20 doubles, 1/1 index. Single `writeDataPoint` per beacon, far under the 250/request cap.

## 2. Shared prerequisites (Phase 0, do once)

### 2.1 `buildWhereClause` — `worker/src/lib/query.ts:103`
Gains **two** filters (traffic-class AND event-type), both defaulting to the human-pageview view:

```ts
export function buildWhereClause(
  opts: QueryOptions,
  extra: { trafficClass?: 'human' | 'ai' | 'all'; eventType?: 'pv' | 'all' } = {},
): string {
  const site = opts.site.replace(/'/g, \"''\");
  const start = formatTimestamp(opts.startAt);
  const end = formatTimestamp(opts.endAt);

  // VERIFIED predicate from PROBE 2: use blob10 = '' if unset blobs are '',
  // else (blob10 = '' OR blob10 IS NULL). Same for blob16.
  const tc = extra.trafficClass ?? 'human';
  const tcClause =
    tc === 'human' ? \" AND blob10 = ''\" : tc === 'ai' ? \" AND blob10 = 'ai'\" : '';

  const et = extra.eventType ?? 'pv';
  const etClause = et === 'pv' ? \" AND (blob16 = 'pv' OR blob16 = '')\" : ''; // '' = legacy/pre-0.3.0 rows are pageviews

  return `WHERE blob1 = '${site}' AND timestamp >= toDateTime('${start}') AND timestamp <= toDateTime('${end}')${tcClause}${etClause}`;
}
```

- Defaults mean **every existing handler automatically excludes both crawler rows and engagement rows** with zero per-handler edits.
- Callers: crawlers passes `trafficClass:'ai'`; bounce/duration pass `eventType:'all'`; any combined dashboard passes `trafficClass:'all'`.
- **Land the filter + the write-side `blob10`/`blob16` tagging in the SAME release.** Filter-without-tag is safe (no crawler/eng rows exist yet); tag-without-filter inflates human dashboards.

### SQL
```sql
SELECT COUNT(DISTINCT index1) AS active_visitors,
       SUM(_sample_interval)  AS recent_pageviews,
       MAX(_sample_interval)  AS max_interval
FROM agent_analytics
WHERE blob1 = '<site>'
  AND timestamp >= toDateTime('<now-Wmin>')
  AND timestamp <= toDateTime('<now>')
  AND blob10 = '' AND (blob16 = 'pv' OR blob16 = '');
```
`COUNT(DISTINCT index1)` is the sampling-aware distinct count (index1 drives sampling). `recent_pageviews` uses `SUM(_sample_interval)`, never `COUNT(*)`. Single row, no GROUP BY.

### API

### Back-compat / honesty
- **Eventual consistency:** WAE rows are queryable seconds-to-minutes after write; the freshest ~1-2 min are systematically undercounted. 5 min is the practical floor — document; do not promise to-the-second accuracy (the honest tradeoff vs Umami's DB-backed `/active`).
- Daily-rotating hash is fine for a sub-day window; a window straddling UTC midnight can briefly double-count one human (documented).

## 6. Feature: Bounce rate + session duration (effort L) — one sessionization problem, two endpoints
Mirrors Plausible/Umami: session = 30-min inactivity window; bounce = single-pageview session; duration = last-minus-first pageview (+ engagement beacon for the last/single page).

### 6.0 Prerequisite
PROBE 1 (§0.1) must be done. If subqueries 4xx, the handler-side-aggregation design below is mandatory.

### Data model
- `blob12 = session_id` = SHA-256(site\\|ip\\|ua\\|`floor(Date.now()/1800000)`\\|HASH_SALT), 32 hex. Written **always**, **no tracker change** (cookieless, server-side, mirrors Umami's time-windowed salt).
- `double4 = engagement_ms` = dwell for this pageview, default 0; populated only by a new pagehide/visibilitychange beacon.
- `blob16 = event_type` flips to `'eng'` for the dwell beacon (the discriminator that keeps engagement rows out of every pageview count — see §1 fix).

### Files
- **`worker/src/lib/visitor.ts`** — add `sessionWindow(epochMs, slot = 1800000) = String(Math.floor(epochMs / slot))`; reuse `hashVisitor` with it. Test: hits 31 min apart -> different session id; 5 min apart -> same.
- **`worker/src/collect.ts`** — `BeaconPayload`: add `em?: number` (engagement_ms) and `t?: 'pv' | 'eng'`. After `hashVisitor`: compute `sessionHash` via `sessionWindow`. Set blob12=`sessionHash` (mutate index 11 of the positional array), `double4 = payload.em || 0`, **`blob16 = payload.t === 'eng' ? 'eng' : 'pv'`**. **The `eng` event is a normal row distinguished ONLY by `blob16='eng'`** — it does NOT need `double1=0` (that was the broken draft idea); the default `eventType:'pv'` filter in `buildWhereClause` excludes it from all pageview counts. Skip the `eng` write on the SPA pushState path (dwell is per full pageview).
- **`worker/src/tracker.ts`** — add one dwell beacon (~150 bytes, keep <2KB): `var t0 = performance.now()` at pageview; on `pagehide`/`visibilitychange(hidden)` fire `send({ sid, url, em: Math.round(performance.now()-t0), t:'eng' })` once (guard with a `sent` flag).
- **NEW `worker/src/api/bounce.ts`** — **single flat `GROUP BY blob12` query; both totals computed in the handler from the one result set** (critic fix — avoids the two-call eventual-consistency skew and the engaged-single-page undercount):
  ```sql
  SELECT blob12 AS session_key,
         SUM(_sample_interval) AS pv_weight,
         COUNT(*)              AS pv_rows,
         MAX(_sample_interval) AS max_interval
  FROM agent_analytics
  WHERE blob1='<site>' AND timestamp >= toDateTime('<start>') AND timestamp <= toDateTime('<end>')
    AND blob10 = '' AND blob12 != '' AND (blob16 = 'pv' OR blob16 = '')   -- pageview rows only; eng rows excluded
  GROUP BY blob12 ORDER BY pv_weight DESC LIMIT 100000;
  ```
  In the handler: `sessions = result.length` (`approx_sessions`); `bounced = count(rows where pv_rows === 1)`; `bounce_rate = bounced / sessions`. **Degrade honestly when sampled:** if any `max_interval > 1`, `pv_rows` is the retained (sampled) row count so `=== 1` is biased upward -> return `bounce_rate: null` + `warning: \"bounce rate unreliable when sampled\"`. Because the `pv` filter excludes the `eng` row, a single-pageview engaged visit correctly has `pv_rows === 1` and counts as a bounce (fixes the draft's systematic undercount). **Never return `blob12` values** — count rows and discard the keys.
- **NEW `worker/src/api/duration.ts`** — flat per-session GROUP BY, average in TS:
  ```sql
  SELECT blob12 AS session_key,
         toUInt32(MAX(timestamp)) - toUInt32(MIN(timestamp)) AS span_s,
         MAX(double4) AS dwell_ms,
         MAX(_sample_interval) AS w,
         MAX(_sample_interval) AS max_interval
  FROM agent_analytics
  WHERE blob1='<site>' AND timestamp >= toDateTime('<start>') AND timestamp <= toDateTime('<end>')
    AND blob10 = '' AND blob12 != ''
  GROUP BY blob12 ORDER BY w DESC LIMIT 100000;
  ```
  Note: duration intentionally does NOT filter `blob16='pv'` — the `eng` row carries `double4` (dwell) and shares the session's `blob12`, so `MAX(double4)` picks it up and `MAX/MIN(timestamp)` are unaffected. Handler: `dur = max(span_s, dwell_ms/1000)` per session (covers single-page via the beacon); `avg_session_seconds = sum(dur * w) / sum(w)`. Document that very high-cardinality windows truncate at the LIMIT.
- **`worker/src/index.ts`** — import + `app.get('/api/bounce', bounceHandler)`, `app.get('/api/duration', durationHandler)`.
- **`cli/src/index.ts`** — `makeCommand('bounce', 'Bounce rate (% single-pageview sessions)')`, `makeCommand('duration', 'Average session duration in seconds')`. No new flags.
- **Tests:** `visitor.test.ts` (sessionWindow boundaries); `bounce.test.ts` + `duration.test.ts` (handler math with mocked `queryAE`; sampled-degrade -> null+warning; engaged single-page with an `eng` row still counts as bounce because the `pv` filter excludes it); `collect.test.ts` (blob12 at index 11, `eng` beacon writes `blob16='eng'` + `double4`).

### API / CLI
- `GET /api/bounce?site=&period=Nd` -> `{ data: { bounce_rate: number|null, approx_sessions, bounced_sessions, warning? }, meta }`.
- `GET /api/duration?site=&period=Nd` -> `{ data: { avg_session_seconds, approx_sessions }, meta }`.
- CLI: `lazyanalytics bounce --site <s> [--period 30d]`, `lazyanalytics duration --site <s>`.

### Back-compat / honesty
- No second AE index possible: `blob12` is a blob, so `COUNT(DISTINCT blob12)` / `result.length` is **unweighted/approximate** — labelled `approx_sessions`.
- **Floored 30-min window != sliding inactivity, AND it inflates bounce rate specifically (critic fix):** a long reading session that straddles a slot boundary splits into 2 sessions, and the tail session inherits continued reading as a fresh single-pageview session — so boundary-split tail sessions are disproportionately single-pageview and push bounce rate up. Documented in the bounce honesty section as an accepted approximation (append-only store can't fix it).
- **Bounce is returned null under sampling** — the only honest option without a per-row entry flag. (Future: a client `is_bounce` signal in `double3` would make bounce a flat `SUM` — out of scope for 0.3.0.)
- Last-pageview dwell is structurally unmeasurable from pageview rows; the pagehide beacon is best-effort (lost on browser kill / mobile backgrounding); `double4=0` legacy rows -> single-page duration 0 (same as Plausible/Umami today).
- `blob12` is an IP+UA-derived salted hash; **never returned in any API response** (bounce and duration both count/aggregate and discard the keys).

## 7. Feature: Long-term retention beyond 90 days (effort L)
Daily R2 rollups of per-site aggregates + a blended `/api/history` read. Mirrors Counterscale's R2 export, but makes the read-back real and uses **plain JSON** (dependency-free bundle; aggregates are tiny; `JSON.parse`-able in-Worker and externally queryable via DuckDB).

### Data model
No AE write-path change. New external R2 storage: bucket `lazyanalytics-archive` bound as `ARCHIVE`, layout `rollups/<site>/<YYYY-MM-DD>.json`. Schema: `{ date, site, sampled, totals:{views, approx_daily_visitors, avg_screen_width}, pages:[...], referrers:[...], geo:[...], browsers:[...], os:[...], device:[...] }`, each dimension capped top-N/day plus an explicit `other` bucket (sum of dropped tail's views, so long-range totals reconcile). Aggregates only — never raw events.

### Files
- **`worker/src/index.ts`** — change `export default app` to `export default { fetch: app.fetch, scheduled }`; add `ARCHIVE?: R2Bucket` to `Env`; import + register `app.get('/api/history', historyHandler)`.
- **NEW `worker/src/scheduled.ts`** — `export async function scheduled(event, env, ctx) { ctx.waitUntil(rollupYesterday(env)); }`.
- **NEW `worker/src/lib/rollup.ts`** — `rollupYesterday(env)`:
  - Guard: `if (!env.ARCHIVE || !env.CF_API_TOKEN) return;`
  - For each site in `parseAllowedSites(env.ALLOWED_SITES)` (per-site try/catch so one failure doesn't abort the run):
    - **Backfill loop:** for each of the last ~88 UTC days still inside AE retention, if `rollups/<site>/<day>.json` is absent in R2, roll it up (self-heals a missed cron run).
    - Roll up yesterday: ~5 flat sampling-aware `GROUP BY` queries (totals, pages=blob2, referrers=blob3, geo=blob4, browsers/os/device=blob5/6/7) with `SUM(_sample_interval)`, `COUNT(DISTINCT index1)`, `MAX(_sample_interval)`, and the default human + `pv` predicate.
    - `await env.ARCHIVE.put(`rollups/${site}/${day}.json`, JSON.stringify(rollup))`.
- **NEW `worker/src/api/history.ts`** — blended read with a **self-correcting per-day boundary (critic fix — no fixed-offset \"85 days\" magic number):**
  - Bypass `parsePeriod`'s 90d cap (own `days`/`from`/`to`). `dimension` param: `totals|pages|referrers|geo|browsers`.
  - For each requested UTC day, decide source by **what actually exists**: if `rollups/<site>/<day>.json` exists in R2 -> serve from archive; else if the day is within AE's live retention window -> serve from live AE; else -> increment `archived_days_missing`. This removes the ~1h daily hole (between 00:00 UTC and the cron at 01:05) and self-corrects against cron lag/failure. The backfill loop's presence check is reused here.
  - **Parallelize R2 reads** (`Promise.all` in chunks of 20-50). Accumulate dimension rows into a Map keyed by dimension value (`views +=`, `approx_visitors +=`), `archiveSampled ||= r.sampled`, track `archived_days_missing`.
  - Merge live rows into the same Map, sort by views, slice to limit.
  - `envelope(rows, site, period, liveSampled || archiveSampled)` with extra meta `source: 'live'|'archive'|'blended'` and `archived_days_missing: N`.
  - **`limit` is a no-op for the SQL itself for unbounded dimensions** — clamp to a large archive cap, document that CLI `-l` doesn't truncate history dimensions.
- **`worker/src/lib/query.ts`** — add `parseLongPeriod` (accepts >90d, history only; the 90d-capped `parsePeriod` stays for live endpoints), `dayKeys(startAt, endAt)`, `mergeRollups(dimension, files)`.
- **`worker/wrangler.toml` + `templates/wrangler.toml`** — `[[r2_buckets]] binding=\"ARCHIVE\" bucket_name=\"lazyanalytics-archive\"` (template token `__ARCHIVE_BUCKET__`) and `[triggers] crons=[\"5 1 * * *\"]`. Opt-out deployments (`--no-archive`) must NOT get these blocks, or deploy fails on a missing bucket.
- **`cli/src/commands/setup.ts`** — `--archive` (default) / `--no-archive`; when on, `wrangler r2 bucket create lazyanalytics-archive` (idempotent, ignore \"already exists\") **before** deploy; substitute `__ARCHIVE_BUCKET__` + the r2/triggers blocks.
- **NEW `cli/src/lib/wrangler.ts` helper** — `wranglerR2BucketCreate(name, env)` mirroring `wranglerSecretPut`/`wranglerDeploy`.
- **`cli/src/index.ts`** — `makeCommand('history', 'Long-term stats blending live AE (<=90d) with R2 archives (>90d)').option('--dimension <d>', 'totals|pages|referrers|geo|browsers', 'totals').option('--days <n>', 'Lookback days (can exceed 90)')`. Thread `--dimension`/`--days` via §2.2.
- **Tests:** `rollup.test.ts` (SQL builders, backfill detects missing days, per-site isolation, `other` bucket, dimension cap); `history.test.ts` (`dayKeys`, **per-day existence boundary = no double-count, no gap, self-corrects against a missing rollup**, `mergeRollups`, visitor-sum semantics, `sampled` OR-ing, `archived_days_missing`) with mocked `queryAE` + mocked R2 get/put.

### SQL (per-site daily rollup — totals + one dimension)
```sql
-- totals
SELECT SUM(_sample_interval) AS views,
       COUNT(DISTINCT index1) AS approx_daily_visitors,
       SUM(_sample_interval * double2) / (SUM(_sample_interval) + 0.0001) AS avg_screen_width,
       MAX(_sample_interval) AS max_interval
FROM agent_analytics
WHERE blob1='<site>' AND timestamp >= toDateTime('<start>') AND timestamp <= toDateTime('<end>')
  AND blob10 = '' AND (blob16 = 'pv' OR blob16 = '');

-- pages (same shape for referrers=blob3, geo=blob4, browsers=blob5, os=blob6, device=blob7)
SELECT blob2 AS page, SUM(_sample_interval) AS views, COUNT(DISTINCT index1) AS approx_visitors,
       MAX(_sample_interval) AS max_interval
FROM agent_analytics
WHERE blob1='<site>' AND timestamp >= toDateTime('<start>') AND timestamp <= toDateTime('<end>')
  AND blob10 = '' AND (blob16 = 'pv' OR blob16 = '') AND blob2 != ''
GROUP BY blob2 ORDER BY views DESC LIMIT 1000;
```
All cross-day merging happens in JS over the R2 JSON — no nested GROUP BY, no window functions.

### API / CLI
`GET /api/history?site=&dimension=&days=<n>` (or `&from=&to=`) -> `{ data, meta: { site, period, sampled, source, archived_days_missing } }`. CLI: `lazyanalytics history -s <s> --dimension pages --days 180`.

### Back-compat / honesty
- Archival starts the day the cron is enabled; days already aged past 90d in AE are unrecoverable. Daily cadence + backfill loop guarantees no NEW day ages out unarchived.
- **Visitors don't sum across days** (index1 is per-visitor-per-DAY): historical \"visitors\" = sum of daily approx-distinct, each a sampled (possibly undercounted) figure frozen at archive time. Never advertise long-range unique visitors. `meta.sampled` ORs across all contributing days; `archived_days_missing` makes holes visible.
- R2 free tier covers this (~$0); R2 must be enabled on the account.
- If sessionization (Feature 6) ships first, add `bounces`/`sessions` fields to the rollup JSON — design the schema additively so old files stay valid.

**Ship 0.3.0** after Phases 4-5. Bump `package.json` to `0.3.0`, `npm run build`, update CHANGELOG/README/SKILL.md (document the WAE subquery limitation, the bounce-under-sampling null, the floored-window bounce inflation, the AI-agent JS-only caveat, the pageview-scoped channels caveat, and the retention visitor-sum caveat).

### Critic fixes incorporated (traceability)
1. **[critical] Engagement-row poisoning** — engagement is NOT a separate full-count row; `blob16` event_type discriminator + default `eventType:'pv'` filter in `buildWhereClause` auto-excludes it from every count.
2. **[critical] Bounce mis-spec** — single flat `GROUP BY blob12` (pageview rows only), both totals computed in the handler from one result set (no two-call skew); engaged single-page correctly counts as bounce; null+warning when sampled.
3. **[high] Active exit code** — dedicated `Command`, explicitly always exit 0 on 200; `active_visitors=0` is valid; test added.
4. **[high] Empty-string predicate unverified** — PROBE 2 mandated in Phase 0; verified predicate baked into `buildWhereClause`.
5. **[high] Channel session-vs-pageview** — metric renamed `pageviews`, documented as pageview-scoped; session-scoped deferred post-0.3.0.
6. **[medium] Floored-window bounce inflation** — named explicitly in bounce honesty section; blob12 never returned by bounce or duration.
7. **[medium] R2 history boundary gap** — per-day R2 existence check, no fixed-offset magic number; self-corrects against cron lag.
8. **[medium] classifyCrawler error default** — resolved to `kind:'bot'` (drop on error); test added.
9. **[medium] Positional blob array** — explicit 16-element contiguous array with `blob12=''` placeholder in 0.2.0; exact length+index test.
10. **[low] Active site guards + history/channels limit** — active replicates missing-site/unknown-site guards; channels/history ignore the inbound `limit` for bounded/archive dimensions (documented no-op)."
